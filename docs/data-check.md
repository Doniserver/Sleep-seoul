# Phase 0 — 데이터 검증 결과

작성일: 2026-11-10 · 대상: S-DoT 주간 CSV 3주(2026-10-12 ~ 11-01) + Open API(2026-11-02 ~ 11-09)

## 결론

**그대로 진행하되, 기간은 축소해서 시작한다.**

- 센서·지표 설계는 계획대로 할 수 있다. 소음·조도 값, KST 시간대, 센서 위치, 지역 구분이 모두 있다.
- 다만 지금 있는 데이터는 **29일 밤**(2026-10-11 밤 ~ 11-08 밤)이다. "최근 12개월"을 채우려면 주간 CSV를 더 받아야 한다(아래 "남은 일").
- 건축물대장은 **공동주택(K-APT) 기본정보 API만 승인**됐다. 단지 목록 API는 아직 "등록되지 않은 서비스키"로 막혀 있어 층간소음 레이어는 대기 중이다.

## 1. S-DoT CSV 구조

| 항목 | 확인 결과 |
|---|---|
| 파일 | `S-DoT_NATURE_YYYY.MM.DD-MM.DD.csv`, 주당 약 60MB, **인코딩 cp949** |
| 칸 수 | 머리글 58칸, **데이터 행 64칸**. 그냥 읽으면 칸이 밀리므로 `index_col=False` 필수 |
| 사용 컬럼 | `시리얼`, `측정시간`, `지역`, `자치구`, `행정동`(영문), `소음 평균(dB)`, `소음 최대(dB)`, `조도 평균(lux)` |
| 단위 | 소음 dB(정수), 조도 lux |
| 측정시간 형식 | `2026-10-26_00:07:00` (매시 07분) |
| 시간대 | **KST**. 등록일시와 1분 차이(중앙값 0.8분). 조도가 0시~6시 0, 7시부터 오름 |
| 측정시간의 뜻 | **그 앞 1시간 구간의 끝**으로 판단. 18:07 표기의 조도 중앙값이 217lux, 19:07은 2lux. 10월 일몰(17:40~18:05)과 맞음. 따라서 구간 시작 = 표기 − 1시간으로 처리 |
| 소음 범위 | 35 ~ 85dB. **35dB가 하한**(그보다 조용해도 35로 기록됨) |
| 모델 | 전부 `SDOT001` |

API(`IotVdata017`)도 같은 값을 영문 필드명(`SN`, `MSRMT_HR`, `AVG_NIS`, `MAX_NIS`, `AVG_INILLU` …)으로 준다. 명세서(20250716)로 확인했다. API는 **최근 한 달만** 제공하고(약 75만 행), 1회 최대 1000건, 자치구·등록일자로 거를 수 있다.

## 2. 소음 "평균"의 계산 방식

명세서와 데이터셋 설명에 1시간 평균의 계산 방식(산술 / 에너지 평균 Leq)이 **적혀 있지 않다**.
→ **산술평균으로 가정**한다. 1시간 안은 이 가정 그대로 두고, 시간들을 합칠 때는 에너지 평균을 쓴다(methodology.md).

## 4. 센서 위치 분류

- `설치 위치정보.xlsx`(2026-03-11 기준, 1,170행, WGS84 위경도)로 **1,070개**를 좌표로 행정동에 넣었다(점-다각형 판정, 행정동 경계 ver20261001).
- 위치 파일에 없는 2026년 신규 센서(`OC3KL26…`) 중 **33개**는 같은 구·같은 영문 동 이름을 가진 센서의 행정동으로 연결했다. 22개는 연결하지 못했다.
- CSV의 `지역` 컬럼이 센서 설치 장소를 이미 구분한다. 행 수 기준:

| 지역 값 | 뜻 | 행 수 | 처리 |
|---|---|---|---|
| residential_area | 주거지역 | 520,452 | **동네 대표값에 사용** |
| roads_and_parks | 도로·공원 | 79,818 | 제외 |
| parks | 공원 | 4,253 | 제외 |
| industrial_area, traditional_markets, main_street, commercial_area, public_facilities | 공업·시장·큰길·상업·공공 | 108,565 | 주거 센서가 없는 동에서만 사용(표시함) |

- 산지·하천변을 따로 표시한 값은 없다. 공원 경계와 겹쳐 보는 일은 하지 않았고, `지역` 값을 그대로 썼다.
- 결과: **427개 행정동 중 398개**에 대표값이 있다(주거 센서 391개 동, 비주거 센서 7개 동). 29개 동은 "데이터 없음".
- 동마다 센서 수: 1개 229곳, 2개 101곳, 3개 38곳, 4개 이상 30곳. **절반 이상이 센서 1개**라서 화면에 경고를 띄운다.

## 5. 건축물대장 / 공동주택

| API | 상태 | 확인한 것 |
|---|---|---|
| 국토교통부 공동주택 기본 정보(`AptBasisInfoServiceV5/getAphusBassInfoV5`) | **작동** | `kaptUsedate`(사용승인일, YYYYMMDD), `bjdCode`(법정동 10자리), `kaptdaCnt`(세대수), `kaptAddr`, `codeAptNm`. **좌표 없음, 구조(벽식·기둥식) 필드 없음** |
| 국토교통부 공동주택 단지 목록(`AptListService4`) | **403 등록되지 않은 서비스키** | — (서울 단지 코드를 얻으려면 필요) |
| 건축HUB 건축물대장 표제부 | 응답 시간 초과(서비스 경로 미확인) | — |

- 좌표가 없어서 "건물 점"은 그릴 수 없다. **법정동 단위로 등급을 세어 이름이 같은 행정동에 연결**한다(역삼1동 → 역삼동).
- 구조 필드가 없어 "기둥식이면 한 단계 낮춤"은 적용하지 않는다.
- 채움률(사용승인일이 비어 있는 단지 비율)은 단지 목록 API가 열리면 측정한다.

| 연도 | 파일 | 형식 | 확인한 문제와 처리 |
|---|---|---|---|
| 2020 (4월~) | 월별 CSV 16개 | 옛 형식 | 소음이 값 하나(`소음(dB)`)뿐, 지역·행정동 없음. 시간은 `등록일자`(`2020.4.1 1:00`) |
| 2021 | 주별 CSV 55개 | 옛 형식 98% + 11월부터 새 형식 | 머리글 변형 4가지(`등록일자`/`등록 일자`, `기관 명`/`기관명` 등). `전송시간`은 숫자가 깨져 있음(`2.02E+11`) → 등록일자 사용 |
| 2022 | 주별 CSV 54개 | 옛 형식 99% | `소음 (㏈)`, `등록 일시` 같은 띄어쓰기·기호 변형 → 띄어쓰기 제거·㏈→dB로 비교 |

| 2024 | 월별 CSV 12개 | 새 형식 | 문제 없음 |
| 2025 | 일별 CSV 235개 | 새 형식 | 문제 없음 |

- 옛 형식에는 지역 구분(주거지역 등)이 없어 같은 시리얼의 이후 연도 값을 붙였다. 찾지 못한 행: 2020년 110, 2021년 7,542, 2022년 5,500 (전체의 0.1% 미만).
- 옛 형식에는 **최대값이 없어 2020~2022년 피크 횟수는 계산하지 않는다**("없음"으로 표시). 옛 형식 '소음' 값이 1시간 평균인지 순간값인지는 공개돼 있지 않다. 2021~2022년(45.4dB)과 2023~2025년(44.4~45.0dB)의 서울 중앙값이 비슷해 비교 가능한 수준으로 보지만, 형식이 바뀐 해의 차이는 해석에 주의한다.
- 서울 행정동 밤 소음 중앙값: 2020 47.5(일부), 2021 45.4, 2022 45.4, 2023 45.0, 2024 44.6, 2025 44.4dB.

## 8. 위치별 추정 검증 (2026-11-12, 2025년 밤 소음 기준)

"센서가 없는 자리의 소음을 주변 자료로 맞힐 수 있는가"를 센서를 하나씩 가리고 확인했다.

| 방법 | 평균 오차 | ±3dB 안 | 순위 상관 |
|---|---|---|---|
| 서울 중앙값 하나로 모두 추정 (기준선) | 5.2dB | 41% | – |
| 가까운 주거 센서 3개로 추정 (주거 센서 630개) | 4.7dB | 41% | 0.06 |
| 도로 거리(2·4·6·8차로) + 술집 수, 10겹 교차검증 (공원 제외 871개) | 4.7dB | 42% | 0.32 |

- 이웃 센서(중앙값 402m 거리)는 서로의 값을 거의 설명하지 못한다. 소음은 동네 단위가 아니라 수십 m 단위로 달라진다.
- 4차로 이상 도로에서 35m 안이면 중앙값 51dB(절반이 50dB 이상), 35m 밖이면 44~45dB(50dB 이상은 14~18%). 경계는 35m 부근에서 계단처럼 나타난다.
- 도로 거리로 설명되는 부분은 전체 차이의 약 20%. 위치별 dB 숫자를 ±3dB로 맞히는 것은 불가능하다고 판단.
- 도로 자료: 브이월드 2D 데이터 API `LT_L_N3A0020000`(연속수치지도 도로중심선), 속성 `rdln`(차로 수)·`rvwd`(폭 m). 서울 2차로 이상 132,480줄 → `pipeline/fetch_roads.py`.
- 술집(상가정보 API 주점 I211, 15,213곳): 100m 안 15곳 이상인 주거 센서 12개가 0곳보다 밤 +2.9dB, 금·토 심야 +3.0dB. 다른 요인을 함께 넣으면 5곳 이상 +2.0dB.
- 김포공항 경로 부근 주거 센서 48개는 다른 곳과 차이 없음(시간 평균으로는 항공기 소음이 드러나지 않음).

### 8-1. 추가 조사 (같은 날)

- 같은 센서는 해마다 거의 같다: 2024↔2025 상관 0.94, 차이 중앙값 0.6dB (2021↔2025는 0.82, 1.5dB).
- 가까운 센서끼리는 다르다: 100~200m 떨어진 쌍 90개의 차이 중앙값 4.3dB(상관 0.33), 400m 이상은 상관 0.03~0.09.
- 센서의 밤 평균과 "가장 조용한 10% 시간" 값의 상관 0.95, 밤↔낮 0.91 → 센서 간 차이는 시간대와 무관한 일정한 높낮이 차이가 대부분. 자리 특성인지 기기·설치 차이인지는 공개 자료로 구분 불가(설치 위치정보에는 주소·좌표만 있고 높이·방향 없음).
- 교통 노출 지표(반경 30m 안 도로의 차로 수×길이)가 단순 거리보다 낫다: 순위 상관 0.38(밤), 0.47(낮).
- 요인 15개(도로 거리·노출·차로 수·폭·술집 수)로 만든 비선형 모델, 5겹 교차검증: 평균 오차 4.6dB, 설명력 0.22 → dB 추정은 여전히 불가.
- 등급으로는 쓸 만하다: 모델이 "시끄러운 쪽 20%"로 본 자리는 59%가 50dB 이상·39%가 55dB 이상, "조용한 쪽 50%"는 13%·3%. 55dB 이상 가려내기 AUC 0.82.
- 60m 안에 2차로 이상 도로가 없는 센서 354개도 39~51dB(10~90%)로 퍼져 있고 14%는 50dB 이상 → 도로로 설명되지 않는 소음이 있음.

## 9. 센서 기종 차이 발견 (2026-11-12) — 가장 중요한 문제

S-DoT 센서는 시리얼 앞자리로 두 기종이 구분된다: `V02Q…`(2025년 유효 656개), `OC3…`(215개, 2021년부터 자료 있음).

| 확인 방법 | OC3 − V02 (밤 소음) |
|---|---|
| 주거지역 센서 중앙값 (53.1 대 43.8) | 9.3dB |
| 150m 안에 나란히 있는 쌍 19개 (95%에서 OC3가 높음) | 10.6dB |
| 위치 요인 101개를 통제한 모델 | 8.5dB |
| OC3로만 배운 모델이 V02 자리에 기대하는 값과 실제의 차이 | 8.1dB |

- 새벽 3~4시에도 차이가 그대로(10.9dB) → 주변 활동이 아니라 기기·설치 방식 차이.
- OC3 주거 센서 53.1dB는 서울시 공식 통계(주거 일반 밤 52dB)와 맞는다. V02가 약 8~9dB 낮게 읽는 것으로 판단. (법정 측정소와의 직접 비교로 확정 필요)
- 같은 V02 센서의 2020→2021 변화 −2.3dB(792개), 이후 해마다 ±0.1(2024만 −0.7, 두 기종 공통) → 2020년은 보정값이 다름.
- 영향: 지금 동 값과 "그 동의 OC3 비율"의 상관 0.55. 시끄러운 상위 20% 동의 47%가 OC3가 있는 동(전체는 18%). `main_street` 유형 32개는 전부 OC3라서, 8절의 "큰길 13dB 차이"에는 기종 차이가 섞여 있었다. 같은 기종 안에서는 4차로 35m 안팎 차이가 V02 4.5dB, OC3 8.2dB.
- V02에 +8.5dB를 더해 맞추면 동 값 중앙이 52.4dB, 분포는 45 미만 2%, 45~50 23%, 50~55 56%, 55~60 18%, 60 이상 2%.

### 9-1. 보정 후 위치별 추정 정확도 (요인 101개, 5겹 교차검증 3회 평균)
